## Описание проекта

Проект реализует веб-приложение для управления рассылками сообщений.  
Пользователи могут создавать клиентов (получателей), шаблоны сообщений, задавать рассылки с периодами отправки и
получать статистику по каждой попытке отправки (успех/неудача, ответ сервера).  
Поддерживается система регистрации, входа, восстановление пароля, разделение ролей (пользователь, менеджер) и
ограничений доступа.

---

## Функциональность

### Основные возможности:

- CRUD — операции для получателей (Clients), сообщений (Templates) и рассылок (Mailings)
- Возможность запуска рассылки вручную через интерфейс и через командную строку
- Логирование каждой попытки отправки письма: время, статус («Успешно»/«Не успешно»), ответ почтового сервера
- Главная страница-панель с показателями: общее число рассылок, активные рассылки, уникальные получатели
- Аутентификация и регистрация пользователей, подтверждение email (если настроено)
- Роли и права:
    - Пользователь — работа только со своими рассылками и клиентами
    - Менеджер — просмотр всех пользователей, клиентов, рассылок; блокировка пользователей; отключение рассылок
- Кэширование представлений и шаблонов для повышения производительности

## Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/KirillKovardakov/MailingService.git
   cd MailingService
   git checkout courses_4


2. Установите зависимости (например, с Poetry или pip):

poetry install

# или

pip install -r requirements.txt

3. Создайте файл .env на основе .env.example и задайте параметры:

DEBUG=True
SECRET_KEY=ваш_секрет
EMAIL_HOST=smtp.example.com
EMAIL_HOST_USER=…
EMAIL_HOST_PASSWORD=…
CACHES_DEFAULT_BACKEND=django.core.cache.backends.locmem.LocMemCache

4. Выполните миграции:

python manage.py migrate

5. Создайте суперпользователя:

python manage.py createsuperuser

6. Запустите сервер разработки:

python manage.py runserver

## Конфигурация

AUTH_USER_MODEL = 'users.CustomUser' — используется кастомная модель пользователя.

Настройки email вынесены во .env.

Настройки кэша (CACHES) и другие параметры среды задаются через переменные окружения.

Сигналы автоматически создают профиль (Profile) для нового пользователя.

## Права и роли пользователей

| Роль                | Возможности                                                                                                     |
|---------------------|-----------------------------------------------------------------------------------------------------------------|
| Пользователь (user) | CRUD для своих клиентов и рассылок; просмотр статистики только по своим рассылкам                               |
| Менеджер (manager)  | Просмотр всех клиентов и рассылок, просмотр списка пользователей, блокировка пользователей, отключение рассылок |

Менеджерские функции доступны только авторизованным пользователям с ролью manager. Проверка осуществляется через
декораторы и миксины.
Кэширование и производительность

Используется декоратор @cache_page(...) на выбранных представлениях для кеширования результата.

В шаблонах при необходимости могут использоваться теги {% cache %} для частичного кеширования.

Настройка CACHES позволяет выбрать backend: локальный (LocMemCache), файловый или распределённый.
